TEventFlags — 32-битные флаги событий
=====================================

([English version](README.md))

Расширение scmRTOS: группа из 32 флагов-бит с блокирующим ожиданием 
одного из флагов или их сочетания. Можно задать тайм-аут ожидания.

Примеры
-------

### Дождаться приёма символа или ошибки из ISR

```cpp
OS::TEventFlags flags;

const uint32_t EF_RX  = 1 << 0;
const uint32_t EF_TX  = 1 << 1;
const uint32_t EF_ERR = 1 << 2;

// В ISR UART (обёртка TISRW обязательна):
OS::TISRW isr;
if (uart.err)
    flags.set_isr(EF_ERR);
else if uart.hasRx()
    flags.set_isr(EF_RX);

// В процессе: ждём приём или ошибку
void proc() {
    for (;;) {
        uint32_t state;
        if (flags.wait(EF_RX | EF_ERR, OS::efWaitAny, 1000, &state)) {
            // state — снимок флагов на момент успеха
            if (state & EF_ERR)
               ...
            if (state & EF_RX)
               ...
        } // иначе — таймаут 1 с
    }
}
```

### Опрос без блокировки

```cpp
if (flags.try_wait(EF_ERR, OS::efWaitAny)) {
    // бит EF_ERR был установлен; он сброшен
}
```

### Ожидание без сброса (можно мониторить события)

```cpp
if (flags.try_wait(EF_RX | EF_TX | EF_ERR, OS::efWaitAny | OS::efNoClear)) {
    if (state & EF_ERR)
       ...
    if (state & EF_RX)
       ...
}
```

Значения флагов «защёлкиваются»: `set()` устанавливает биты и они
остаются до явного сброса или до ожидания без `efNoClear`.

Процесс, разбуженный `set()`, может обнаружить, что его условие ещё
не выполнено (нет нужной комбинации битов), — и продолжить ждать.

Подключение
-----------

Штатный механизм scmRTOS: добавить

```cpp
#include "event_flags.h"
```

в файл настроек проекта `scmRTOS_extensions.h` — после этого расширение
доступно во всех единицах трансляции, подключающих `scmRTOS.h`. Это не
исключает необходимости добавить каталог `ext/event-flags` в список
include-каталогов проекта.

API
---

```cpp
enum TEventFlagsOptions : uint32_t {
    efWaitAny  = 0,   // проснуться, когда установлен ЛЮБОЙ из запрошенных битов
    efWaitAll  = 1,   // проснуться, когда установлены ВСЕ запрошенные биты
    efNoClear  = 2    // не сбрасывать запрошенные биты при успехе
};

class TEventFlags {
    bool     wait     (uint32_t Bits, uint32_t Options, timeout_t timeout, uint32_t* Result = 0);
    bool     try_wait (uint32_t Bits, uint32_t Options, uint32_t* Result = 0);
    uint32_t set      (uint32_t Bits);   // возвращает значение после установки
    uint32_t set_isr  (uint32_t Bits);   // версия для ISR
    uint32_t clear    (uint32_t Bits);   // возвращает значение до сброса
    uint32_t get      () const;          // текущее значение, без сброса
    bool     has_waiters () const;       // есть ли сейчас ожидающие в wait()
};
```

- `wait()` — блокирует процесс до выполнения условия, по истечении
  `timeout` возвращает `false`. `timeout == 0` — ждать вечно
  (соглашение scmRTOS). Таймаут — абсолютный: повторные пробуждения
  внутри `wait()` его не обнуляют.
- `wait()`/`try_wait()` возвращают в `Result` всё значение флагов
  **до** сброса запрошенных битов.
- `Bits == 0` — ошибка параметра, `wait()`/`try_wait()` возвращают `false`.
- Блокирующие `wait()` — только из процессов; из ISR — только
  `set_isr()` внутри обёртки `OS::TISRW`.


### Несколько процессов-ожидающих

`set()` будит ВСЕХ ожидающих (`resume_all`), а не одного; каждый проснувшийся
процесс заново проверяет своё условие — свой набор `Bits` и свои `Options`.
Поэтому возможны варианты:

- **Ждут разные (непересекающиеся) биты** — каждый получает своё событие:
  сбрасываются только запрошенные биты, чужие не «съедаются». Процессы не
  мешают друг другу.
- **Ждут один и тот же бит без `efNoClear`** — событие достаётся только
  одному: первым после `set()` выполняется старший по приоритету из
  разбуженных, он и потребляет (сбрасывает) свои биты. Остальные проснутся,
  увидят, что условие уже не выполнено, и уйдут обратно спать с остатком
  таймаута (абсолютный дедлайн не обнуляется) — до следующего `set()` или
  таймаута.
- **То же, но с `efNoClear`** — все ожидающие успешно добирают биты (никто
  не сбрасывает), сброс — только явным `clear()`.

Замечания
---------

- Объект `TEventFlags` занимает `sizeof(TProcessMap) + sizeof(uint32_t)`
  (TProcessMap — 8/16/32 биты в зависимости от `scmRTOS_PROCESS_COUNT`).
- `has_waiters()` может быть полезен владельцу объекта перед его разрушением.
- Ожидание с `efWaitAll` не «съедает» биты, не входящие в `Bits`:
  сбрасываются только запрошенные биты (и то не при `efNoClear`).
