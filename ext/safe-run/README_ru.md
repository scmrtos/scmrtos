safe_run — запуск ядра с проверкой набора процессов на этапе компиляции
=======================================================================

([English version](README.md))

Расширение scmRTOS: `OS::safe_run()` — замена `OS::run()`, которая
дополнительно проверяет **на этапе компиляции**, что список процессов полон
и непротиворечив.

Инвариант scmRTOS: каждый приоритет `pr0..pr(PROCESS_COUNT-1)` должен быть
занят ровно одним процессом. Обычный `OS::run()` пропущенный или дублирующийся
приоритет не замечает: ядро натыкается на `nullptr` в `ProcessTable[]` уже в
рантайме, обычно внутри `system_timer()`. `safe_run()` превращает это в
ошибку компиляции.

Подключение
-----------

Штатный механизм scmRTOS: добавить

```cpp
#include "safe_run.h"
```

в файл настроек проекта `scmRTOS_extensions.h` — после этого расширение
доступно во всех единицах трансляции, подключающих `scmRTOS.h`. Это не
исключает необходимости добавить каталог `ext/safe-run` в список
include-каталогов проекта. Расширение — только заголовочный файл, ничего
компилировать не нужно.

API
---

```cpp
namespace OS {
    // Запуск ядра; проверка происходит на этапе компиляции.
    template<class... Procs>
    NORETURN void safe_run(Procs&... procs);

    // Сам проверщик, можно использовать в своём static_assert:
    template<class... Procs>
    class ProcListCheck {
        static constexpr bool check();
    };
}
```

`safe_run(proc_a, proc_b, ...)` принимает ссылки на все объекты процессов и
проверяет, что их приоритеты образуют ровно множество `pr0..pr(PROCESS_COUNT-1)`:

- **пропущенный приоритет** — процесса какого-то приоритета нет в списке;
- **дубликат приоритета** — переданы два процесса одного приоритета;
- **вне диапазона** — `prIDLE` или приоритет выше `PROCESS_COUNT-1`.

Любое нарушение останавливает сборку `static_assert`-ом с сообщением
«each priority pr0..pr(PROCESS_COUNT-1) must be occupied by exactly one
process». Порядок аргументов не важен — проверка идёт по множеству
приоритетов, а не по позициям.

Если проверка пройдена, `safe_run()` просто вызывает `OS::run()`.

Пример
------

```cpp
// Типы процессов — чистый OS::process, не производные классы:
typedef OS::process<OS::pr0, 512> TProcBlink;
typedef OS::process<OS::pr1, 256> TProcSensor;

TProcBlink  proc_blink;     // регистрация происходит при создании объекта
TProcSensor proc_sensor;

// Тела процессов — явная специализация exec():
template<> void TProcBlink::exec()  { for (;;) { ... } }
template<> void TProcSensor::exec() { for (;;) { ... } }

int main() {
    ...
    OS::safe_run(proc_blink, proc_sensor);   // pr0 + pr1 — всё в порядке
}
```

Теперь уберите `proc_sensor` (оставив `scmRTOS_PROCESS_COUNT = 2`) или
передайте его дважды — сборка остановится с сообщением `static_assert`
вместо падения в рантайме.

Замечания
---------

- Типы процессов, **унаследованные** от `OS::process`, не распознаются —
  расширение сопоставляет точный шаблон `OS::process<pr, stk...>`,
  производный класс даст ошибку компиляции. Вместо наследования используйте
  `typedef`/псевдоним `OS::process`.
- `safe_run()` не создаёт процессы — они регистрируются в ядре как обычно
  (в конструкторе объекта). Расширение только проверяет список и запускает
  ядро.
- Проверка охватывает только переданные аргументы. Процесс, который
  создан, но не передан в `safe_run()`, в проверке не участвует — передавайте
  ВСЕ объекты процессов, иначе проверка теряет смысл.
- Не смешивайте с `OS::launch()`: в одной сборке процессы создаёт что-то
  одно — либо `launch` (у него свой static_assert), либо объекты процессов
  с `safe_run`.
