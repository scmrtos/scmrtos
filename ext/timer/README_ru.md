TSoftwareTimer — программные таймеры на колбэках
=================================================

([English version](README.md))

Расширение scmRTOS: таймерные объекты, которые вызывают колбэк-функцию
через заданное число тиков, однократно или периодически. Таймеры
обслуживает одна функция-диспетчер `service()`, вызываемая один раз за тик
независимо от числа работающих таймеров; штатный источник тиков — хук
системного таймера (`scmRTOS_SYSTIMER_HOOK`).

Колбэк исполняется в контексте того, кто вызывает `service()` (при штатной
интеграции — прерывание системного таймера), поэтому он обязан быть
коротким и неблокирующим: только ISR-безопасные операции (см. раздел об ISR
основной документации scmRTOS).

Подключение
-----------

Расширению нужно лишь одно: `service()` должен вызываться ровно один раз за
тик и ровно из одного контекста. Штатная интеграция — хук системного
таймера, два шага:

1. добавить каталог `ext/timer` в пути поиска заголовков и файл `timer.cpp`
   в список компилируемых исходников (заголовок можно подключать напрямую
   где нужно, либо через `scmRTOS_extensions.h`);

2. установить `scmRTOS_SYSTIMER_HOOK_ENABLE = 1` в `scmRTOS_CONFIG.h` и
    вызвать диспетчер из пользовательского хука:

```cpp
void system_timer_user_hook()
{
    OS::TSoftwareTimer::service();
}
```

Пока `service()` не вызывается каждый тик, таймеры не тикают. Если тот же
хук нужен другому коду расширений — вызывайте все диспетчеры из одной
функции-хука.

Другие допустимые источники тиков — ISR аппаратного таймера или процесс-
обслуживатель. Оба требуют соблюдения правила: `service()` не реентерабелен,
второй вызов, вложившийся в первый (пока исполняется чей-то колбэк),
удвоит декременты и перемешает диспетчеризацию. Процесс к тому же занимает
слот приоритета, а его `sleep(1)` добавляет к тикам джиттер — хук свободен
от обоих недостатков.

API
---

```cpp
class TSoftwareTimer {
    typedef void (*callback_t)(void* arg);

    TSoftwareTimer(callback_t cb, void* arg, bool periodic);
    ~TSoftwareTimer();                       // снимает с регистрации

    bool start(timeout_t ticks);   // старт/перезапуск; false, если ticks == 0
    bool stop();                   // false, если таймер не шёл
    bool is_running() const;

    static void service();         // один раз за тик, из одного контекста
};
```

- `start()` запускает таймер: колбэк сработает через `ticks` тиков. Вызов
  `start()` на работающем таймере перезапускает его. `ticks == 0` —
  недопустимый период, функция возвращает `false`.
- У однократного таймера (`periodic == false`) колбэк срабатывает один раз;
  периодический перезагружается автоматически. Перезагрузка считается от
  точки истечения, поэтому период не дрейфует со временем.
- Все методы неблокирующие и вызываемы и из процессов, и из ISR
  (реестр правится только под `TCritSect`).
- Колбэк может вызывать любые методы таймеров, включая перезапуск и удаление
  собственного таймера — состояние регистрации обновляется до вызова.

Примеры
-------

### Периодическая задача без отдельного процесса

```cpp
void flush_led(void* arg)        // исполняется в ISR системного таймера
{
    gpio_toggle();               // должно быть коротким и неблокирующим
}

OS::TSoftwareTimer blinker(flush_led, 0, true);
...
blinker.start(500);              // переключать каждые 500 мс
```

### Пробуждение процесса по таймеру

```cpp
void on_timeout(void* arg)
{
    static_cast<OS::TEventFlag*>(arg)->signal_isr();
}

OS::TEventFlag watchdog_kick;
OS::TSoftwareTimer wdt(on_timeout, &watchdog_kick, true);

void supervisor() {
    wdt.start(1000);
    for (;;) {
        watchdog_kick.wait(1500);    // таймер будит нас раз в секунду
        ...
    }
}
```

Примечания
----------

- Объект `TSoftwareTimer` занимает примерно 4 указателя плюс всё, что делает
  колбэк.
- Таймер вне реестра (не запускался, уже истёк, остановлен) ничего не стоит
  в `service()`: в списке висят только идущие таймеры.
- Удаление таймера из ISR, который вложился в системный тик ровно во время
  исполнения колбэка этого же таймера, может всё же позволить колбэку
  завершиться последний раз (его копия `(cb, arg)` взята до удаления).
  Память при этом цела; возможен только последний вызов.
- База времени — тик вызывающего `service()`; максимальный период —
  диапазон `timeout_t`, типа таймаута, определяемого в конфигурации проекта.
