launch — создание процессов из списка описаний и запуск ядра
============================================================

([English version](README.md))

Расширение scmRTOS: `OS::launch()` создаёт все процессы из списка inline-описаний
и запускает ядро. Не нужно объявлять типы процессов и специализировать
`exec()` — тело процесса это любой вызываемый объект (функция или лямбда,
можно с захватами).

Приоритет процесса определяется позицией в списке: первое описание получает 
старший приоритет (`pr0`), дальше — по убыванию.

Описаний в списке должно быть ровно `scmRTOS_PROCESS_COUNT`, если это не так,
то компиляция завершается ошибкой (static_assert).

Подключение
-----------

Штатный механизм scmRTOS: добавить

```cpp
#include "launch.h"
```

в файл настроек проекта `scmRTOS_extensions.h` — после этого расширение
доступно во всех единицах трансляции, подключающих `scmRTOS.h`. Это не
исключает необходимости добавить каталог `ext/launch` в список
include-каталогов проекта. Расширение — только заголовочный файл, ничего
компилировать не нужно.

API
---

```cpp
namespace OS {
    // Описание процесса: размер стека в байтах, стартовое состояние, имя, тело.
    template<size_t Stk, TProcessStartState Pss = pssRunning, class F>
    proc_desc<...> proc(const char* name, F&& body);

    // Создать процессы и запустить ядро; не возвращается никогда.
    template<class... Desc>
    NORETURN void launch(Desc... desc);

    // Доступ к уже созданным процессам (когда ОС работает):
    TBaseProcess& proc_by_prio(TPriority pr);
    TBaseProcess& proc_by_idx(size_t i);   // индекс в списке launch()
}
```

- **Тело** — основная функция процесса (аргумент `body` в `OS::proc()`),
  код, который выполняется в процессе. Это любой объект, вызываемый без
  аргументов: обычная функция, указатель на функцию или лямбда (можно
  с захватами). Выполнение начинается при старте процесса, и тело
  **никогда не должно возвращаться** (ожидается бесконечный цикл; возврат
  приводит к зависанию в бесконечном цикле). Замыкание лямбды хранится
  внутри объекта процесса, поэтому захваты по ссылке обязаны переживать
  процесс.
- **Имя** используется только при `scmRTOS_DEBUG_ENABLE == 1`.
- **Стартовое состояние**: `OS::proc<stk, OS::pssSuspended>("имя", тело)`
  создаёт приостановленный процесс (требует `scmRTOS_SUSPENDED_PROCESS_ENABLE == 1`,
  иначе static_assert). Запустить его позже — через `proc_by_prio()` /
  `proc_by_idx()`.
- **Память**: объекты процессов размещаются placement new в одном статическом
  буфере размера, вычисленного на этапе компиляции (сумма размеров объектов,
  каждый округлён до максимального выравнивания набора) — расход ОЗУ виден
  в отчёте `size` линкера.

Пример
------

```cpp
int main() {
    InitHw();

    OS::launch(
        // pr0 — высший приоритет: моргать светодиодом
        OS::proc<1200>("blink", [] {
            for (;;) {
                led.toggle();
                OS::sleep(100);
            }
        }),
        // pr1 (обычная функция где-то в проекте)
        OS::proc<256>("sensor", sensorTask),
        // pr2
        OS::proc<128>("idle_loop", [] {
            for (;;)
                OS::sleep(1000);
        })
    );
}
```

Приостановленный процесс, который запускает другой процесс:

```cpp
OS::launch(
    OS::proc<256>("master", [] {
        for (;;) {
            ...
            OS::proc_by_prio(OS::pr1).start();   // разбудить worker
            ...
        }
    }),
    OS::proc<256, OS::pssSuspended>("worker", [] {
        for (;;) { ... }
    })
);
```

Замечания
---------

- `launch()` обязан быть **единственным** создателем процессов в сборке:
  не смешивайте его с объектами процессов-глобалами или другими создателями
  процессов. При `scmRTOS_DEBUG_ENABLE == 1` занятый до `launch()` слот
  `ProcessTable[]` приводит к остановке в бесконечном цикле (в отладке
  видны `pr` и `ProcessTable[]`); в релизной сборке такой проверки нет.
- Не вызывайте `proc_by_prio()` / `proc_by_idx()` до запуска ОС.
- Индексы `proc_by_idx()` молча съезжают при правке списка launch — для
  перекрёстных ссылок на конкретный процесс надёжнее `proc_by_prio()`.
- Не поддерживается при `SEPARATE_RETURN_STACK != 0` (ошибка `#error` на
  этапе компиляции).
