TSemaphore — счётный семафор
============================

([English version](README.md))

Расширение scmRTOS: классический счётный семафор.
Не имеет владельца, освобождать (`release()`) может любой процесс, 
а не только захвативший; также можно освобождать из ISR — 
`release_isr()`; любой процесс может узнать текущее количество токенов.

Ожидание семафора - не FIFO: `release()` будит не первого в очереди, 
а *старшего по приоритету* (`resume_next_ready()`) — (это обычная практика в scmRTOS).

Подключение
-----------

Штатный механизм scmRTOS: добавить

```cpp
#include "semaphore.h"
```

в файл настроек проекта `scmRTOS_extensions.h` — после этого расширение
доступно во всех единицах трансляции, подключающих `scmRTOS.h`. Это не
исключает необходимости добавить каталог `ext/semaphore` в список
include-каталогов проекта, и файл semaphore.cpp в список файлов для компиляции.

API
---

```cpp
class TSemaphore {
    TSemaphore(size_t max_count, size_t initial_count);

    bool   acquire     (timeout_t timeout = 0);  // false по таймауту
    bool   try_acquire ();                       // не блокирует процесс
    bool   release     ();   // false, если счёт уже равен MaxCount
    bool   release_isr ();   // версия для ISR
    size_t get_count     () const;               // текущее число токенов
    size_t get_max_count () const;
    bool   has_waiters   () const;               // есть ли сейчас ожидающие в acquire()
};
```

- `acquire()` забирает один токен, если есть свободные, либо блокирует процесс 
  до появления свободного токена (когда кто-то вызовет `release()`), или до
  истечения `timeout`; по таймауту возвращает `false`. `timeout == 0` —
  ждать вечно (соглашение scmRTOS).
- `release()` возвращает один токен в свободные, и будит старшего по приоритету ожидающего.
  Возвращает `false`, если счёт токенов уже на максимуме (`max_count`).
- Блокирующие вызовы `acquire()` — только из процессов;
  из ISR — `release_isr()` внутри обёртки `OS::TISRW`.

Примеры
-------

### Ограничить число одновременных обращений к пулу ресурсов

```cpp
OS::TSemaphore buffers(4, 4);    // 4 буфера, все свободны

void worker() {
    for (;;) {
        if (buffers.acquire()) {         // ждём свободный буфер
            ...                          // работаем с ним
            buffers.release();           // возвращаем
        }
    }
}
```

Несколько процессов `worker()` с разными приоритетами работают параллельно;
в пуле в любой момент не больше четырёх, а при возврате буфера токен
получает старший по приоритету из ожидающих.

### Попытка без блокировки

```cpp
if (buffers.try_acquire()) {
    // токен получен; иначе пул пуст — делаем что-нибудь другое
    ...
    buffers.release();
}
```

### Дождаться сигнала из ISR (некий аналог TEventFlag)

```cpp
OS::TSemaphore rx_ready(1, 0);   // бинарный семафор, изначально пуст

// В ISR UART (обёртка TISRW обязательна):
OS::TISRW isr;
rx_ready.release_isr();

// В процессе:
void proc() {
    for (;;) {
        if (rx_ready.acquire(1000)) {
            // пришёл байт
            ...
        } // иначе — таймаут 1 с
    }
}
```


Замечания
---------

- Объект `TSemaphore` занимает `sizeof(TProcessMap) + 2 * sizeof(size_t)`
  (TProcessMap — 8/16/32 биты в зависимости от `scmRTOS_PROCESS_COUNT`).
- `has_waiters()` может быть полезен владельцу объекта перед его разрушением.
- Наследования приоритетов нет (нет и владельца, которому оно принадлежало
  бы). Если нужна блокировка с владельцем — используйте `OS::TMutex`.
