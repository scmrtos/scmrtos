Порт scmRTOS для Linux (тестовый)
=================================

([English version](README.md))

Порт запускает ядро scmRTOS как обычную программу Linux. Он предназначен для
отладки и тестирования ядра, сервисов, расширений и прикладной логики без
целевой платы: с отладчиком, санитайзерами и в CI.

Как устроен
-----------

Вся ОС выполняется в одном потоке Linux.

| Понятие scmRTOS | Реализация в порте |
| --- | --- |
| Контекст процесса | `ucontext_t`, переключение `swapcontext()` |
| «Указатель стека» процесса | адрес его `ucontext_t` |
| Прерывание | сигнал POSIX |
| Системный таймер | `SIGALRM` (от `setitimer()` или `OS::sim_tick()`) |
| Программное прерывание переключения контекста (схема 1, аналог PendSV) | `SIGRTMIN+8` |
| Пользовательские прерывания 0..7 | `SIGRTMIN+0` … `SIGRTMIN+7` |
| Критическая секция | `sigprocmask()` блокирует все сигналы порта |

Обработчики «прерываний» не вкладываются: внутри обработчика все сигналы
порта заблокированы. Если ожидают несколько прерываний, первым обрабатывается
системный таймер, затем пользовательские по возрастанию номера, последним —
переключение контекста. Так оно ведёт себя как PendSV с низшим приоритетом на
Cortex‑M: прерывание, ожидавшее в момент запроса переключения, выполняется
раньше и может изменить выбор процесса. Порядок держится именно на всеобщей
блокировке: при пустом `sa_mask` Linux складывает фреймы обработчиков стопкой
и исполняет их в обратном порядке — от старшего номера сигнала к младшему.
Отличие от Cortex‑M: там таймерное прерывание обычно стоит ниже
пользовательских (их приоритет NVIC выбирает приложение), здесь — выше всех.

Новый процесс начинает работу с запрещёнными прерываниями и разрешает их сам:
`swapcontext()` устанавливает маску сигналов раньше, чем переключает регистры,
поэтому входить в контекст с открытой маской нельзя.

Настройка
---------

Параметры задаются в `scmRTOS_TARGET_CFG.h` проекта или ключами `-D`.

| Макрос | Значения | По умолчанию |
| --- | --- | --- |
| `scmRTOS_CONTEXT_SWITCH_SCHEME` | 0 — прямое переключение в планировщике; 1 — через программное прерывание, тот же путь кода, что у Cortex‑M и Zynq‑7000 | 0 |
| `scmRTOS_PRIORITY_ORDER` | 0 — возрастающий, 1 — убывающий порядок приоритетов | 0 |
| `scmRTOS_LINUX_TICK_MODE` | 0 — ручные тики через `OS::sim_tick()`, детерминированно; 1 — реальное время, `SIGALRM` | 0 |
| `scmRTOS_LINUX_TICK_PERIOD_US` | период системного таймера в режиме реального времени, мкс | 1000 |
| `scmRTOS_LINUX_PRIO_MASK_TABLE` | 1 — `get_prio_tag()` читает динамически инициализируемую таблицу, как порты AVR/MSP430/STM8 | 0 |
| `scmRTOS_LINUX_MIN_STACK_SIZE` | минимальный стек процесса, байт; проверяется при `scmRTOS_DEBUG_ENABLE == 1` | 16384 |

API порта
---------

```cpp
OS::sim_tick();                              // сделать один тик системного таймера
OS::host::set_irq_handler(n, handler);       // задать обработчик пользовательского прерывания n (0..7)
OS::host::raise_irq(n);                      // активировать прерывание n
OS::host::irq_signal(n);                     // выдать номер сигнала прерывания n, например для timer_create()
get_interrupt_state();                       // 1 — прерывания запрещены (критическая секция, обработчик)
```

При помощи макроса `scmRTOS_LINUX_CRITSECT_EXIT_HOOK` можно задать функцию
(`extern "C" void f()`), которую порт будет вызывать при каждом выходе из
самой внешней критической секции, то есть в каждой точке, где в условиях микроконтроллера
сработало бы ожидающее прерывание. Регрессионные тесты могут использовать этот хук,
чтобы подавать прерывания во все такие точки.

Запрошенное внутри критической секции прерывание срабатывает при выходе из
неё — как на реальном контроллере. Обработчик пишется так же, как в других
портах:

```cpp
static void uart_rx_irq()
{
    OS::TISRW isr;               // обязательно первым
    RxFlag.signal_isr();
}
```

Ограничения
-----------

- **Только glibc.** `makecontext()` должен строить кадр от вершины стека, как
  это делает glibc. Порт проверен на x86‑64.
- **Переполнение стека не обнаруживается.** При `scmRTOS_DEBUG_ENABLE == 1`
  порт проверяет размер стека при старте, а `stack_slack()` показывает запас;
  без отладки нижняя граница стека порту неизвестна.
- **Стеки процессов от 16 КиБ.** Обработчики сигналов выполняются на стеке
  прерванного процесса, отдельного стека прерываний нет.
- **libc не реентерабельна.** В режиме реального времени процесс может быть
  вытеснен внутри `printf()` или `malloc()`. Вызывайте их под мьютексом
  (`OS::TMutexLocker`) или в критической секции.
- **Тики могут теряться.** Обычные сигналы не накапливаются: если Linux снимет
  процесс с CPU дольше периода таймера, несколько `SIGALRM` сольются в один.
  Время ОС при этом остаётся согласованным, но отстаёт от реального.
- **`SIGALRM` занят.** Не используйте в приложении `alarm()`, `sleep()` libc,
  `setitimer(ITIMER_REAL)` и сигналы `SIGRTMIN..SIGRTMIN+8`.
- **Один поток.** Вызывать функции ОС из других потоков Linux нельзя.
- **Санитайзеры.** UndefinedBehaviorSanitizer работает без оговорок.
  AddressSanitizer работает с `ASAN_OPTIONS=detect_stack_use_after_return=0`:
  порт сам снимает «отравление» стека процесса при его (пере)запуске, но
  аннотаций переключения стеков (`__sanitizer_start_switch_fiber`) в нём нет.
